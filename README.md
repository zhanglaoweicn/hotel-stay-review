# 好评文案助手 · 静态版（GitHub Pages 可用）

由 `haoping-delivery` 改造而来，去掉了服务端和 AI 依赖，
现在是一个**纯静态单页**，可以直接部署到 GitHub Pages。

---

## 一、这个版本和原版的区别

| | 原版 `app/` | 本静态版 |
|---|---|---|
| 需要后端 | 是（`server.js`） | **否** |
| 需要 API 密钥 | 是（DeepSeek） | **否** |
| 生成方式 | 大模型 + 本地模板兜底 | **本地模板引擎** |
| 生成速度 | 3～6 秒 | **即时** |
| 部署方式 | WorkBuddy / PaaS | **GitHub Pages 等静态托管** |
| 费用 | 按量计费 | **零** |

改造点只有一处逻辑：把「优先调 AI，失败降级本地」改成「直接用本地引擎」。

文案质量不用担心——`engine2.js` 是一个词级槽位引擎，
自带结构洗牌、词面变异和 4-gram 相似度闸门，
实测连续生成 8 次全不重复，两两最高相似度仅 17.2%（阈值 30%）。

## 二、部署到 GitHub Pages

### 第1 步：建仓库

新建一个仓库，例如 `hotel-stay-review-static`，选 **Public**（Pages 免费版要求公开）。

### 第 2 步：上传文件

把下面两个文件传到仓库**根目录**：

```
index.html
engine2.js
```

> 注意：本目录里还有 `README.md`，可以一起传，也可以删掉。

### 第 3 步：开启 Pages

1. 仓库页面 →顶部 **Settings**
2. 左侧菜单 → **Pages**
3. Source 选 **Deploy from a branch**
4. Branch 选 **main**（或master），目录选 **/ (root)**
5. 点 **Save**

等 1～2 分钟，页面下方会显示：

```
Your site is live at https://你的用户名.github.io/hotel-stay-review-static/
```

这就是给顾客扫的那个二维码指向的地址。

### 第 4 步：生成物料二维码

回到原交付包的 `qr-tool/` 文件夹（双击 `index.html` 离线可用），
把上面拿到的链接粘进去，下载 1024×1024 的 PNG 即可。

## 三、后续想换回 AI 版

这个静态版是「够用且免费」的版本。如果哪天想恢复 AI 文案，
把原版 `app/` 目录按README 走PaaS 部署即可，两者互不影响。

也可以做一个混合方案：静态页放 GitHub Pages（前端），
AI 接口单独部署到一个小服务（后端），前端改为跨域调用——
但这需要处理 CORS 和接口鉴权，收益有限，
一般不建议为了「文案更长一点」引入这层复杂度。

## 四、合规提醒

美团 / 携程 / 飞猪均禁止诱导、利诱好评。

这个工具的护栏是刻意设计的：**只写顾客自己勾选的方面，
不编造「带着孩子」「出差路过」这类顾客没说过的事实。**

静态版尤其要注意——GitHub Pages 默认公开可搜索，
全网任何人都能搜到这个页面并使用它。

建议：
- 在前台物料上写明「本店提供辅助撰写工具，请按真实感受填写」
- 不要主动对外大范围推广这个链接
- 若只想给自己/合作门店用，可以把仓库设为私有，
  再用 GitHub Pages 的付费私有方案，或直接用 Netlify/Vercel 私有部署
